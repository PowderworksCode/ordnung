    mutable ref, which Ordnung's own `pinned-actions` check rejects as
    required. Chicken-and-egg with the release. Leaning: tag an early
    0.1.0-rc so workflows can pin a real revision.

1.2 test-mirror: 262 of 354 local findings (74%).
    Requiring one test file per source file is the single biggest item
    on the board. It is allow_override = true, so members can carry a
    documented exception while the backlog is worked down. Decision
    needed: work through it, grant exceptions, or reconsider the rule.
    Note test-inline (the "no inline #[cfg(test)]" half) is only 35
    findings and is the part originally asked for.

1.3 Promote website/.githooks into conf as managed content?
    website/.githooks is the only real hooks implementation in the
    fleet (commit-msg enforcing Conventional Commits, pre-commit
    running the gate, run-straitjacket helper). Distributing it via
    conf would fix six of the seven git-hooks failures at once. Not
    done: hook contents are a content decision, and run-straitjacket
    assumes straitjacket is on PATH.

1.4 Vale and Stylelint configs.
    paranoid requires both. No .vale.ini anywhere except website; no
    Stylelint config anywhere (ordnung/site fails it). Needs a prose
    style decision before conf can distribute them as managed files.

1.5 Graduation preview.

1.6 straitjacket's stage.

== 2. DECIDED — DO NOT RELITIGATE ==

- paranoid is the target; incubating is temporary scaffolding.
- All 7 members are incubating today. Graduating one is a deliberate
  edit to conf/.ordnung/fleet.toml.
- Stage is fleet-assigned, never self-declared by a member.
- conf is private. ordnung, entl, straitjacket, infact, cowbird are
  public; website is private.
- Managed-entry override is name-keyed only. Cross-layer collisions
  between differently named entries stay an error.
- present / absent / unmanaged are three distinct states.
- Downstream layers may override anything they inherit; allow_override
  governs member repositories only.
- Config lives in .ordnung/ ; the directory is the unit of publication.
- Built-in defaults are the industry floor (17 required / 21
  recommended / 7 off). Tool mandates and house conventions belong in
  a tier, not in defaults.
- Rust required dependency: itertools. TypeScript: remeda, ts-pattern,
  zod.
- repo-check does NOT take --fleet. Member workflows run the fast gate
  at built-in defaults; conf runs the fleet-aware audit. Reason: conf
  is private, so --fleet would put FLEET_GITHUB_TOKEN into five public
  repositories just to perform a read. If member-side fleet awareness
  is needed later, distribute a fleet-owned policy snapshot as managed
  content rather than fetching conf.

== 4. KNOWN GAPS AND SHARP EDGES ==

- CheckScope is declared on all 47 checks but is not yet consumed by
  policy. It is groundwork for directory-scoped rules. Without it a
  path-scoped rule aimed at a repository-scoped check such as
  branch-protection would silently do nothing.

- Directory-level policy is designed but not built. If it happens:
  prefer the existing project selector (language / ecosystem /
  capability) over raw path globs, since paths are brittle under the
  churn monorepos actually see. Add `path` only as an escape hatch.
  Do NOT add cascading per-directory config files.

- Check configuration does not travel through fleet policy, only
  severities do. TestLayoutConfig lives in RepoConfig, so its ignore
  list and per-language roots are per-repository. This is why
  scan_inline / require_mirror became two checks rather than staying
  two booleans.

- Two checks cannot pass on private repos on the free org plan:
  ruleset-bypass returns HTTP 403, secret-scanning is not offered.
  Affects conf and website. They skip, so they do not gate.

- ruleset-bypass only passes when a gating ruleset EXISTS and has a
  bypass actor. With no rulesets it skips forever. Creating them was
  deliberately deferred until workflows exist, so required status
  checks can be designed at the same time.

- Demoting a check also demotes its errors. An unreadable GitHub
  setting on an advisory check no longer makes a report unclean. This
  is intended; it is documented in design.md.

- Managed entry names are the public interface of a published
  configuration. Renaming one is a breaking change for importers.

- The Git fetch path for extends requires the server to allow fetching
  an arbitrary SHA (uploadpack.allowAnySHA1InWant). GitHub allows it;
  a default-configured self-hosted Git server would reject a pinned
  fetch. Relevant if outside parties publish confs.

- Cargo cannot fetch git dependencies on this machine without
  CARGO_NET_GIT_FETCH_WITH_CLI=true, because a global insteadOf rule
  rewrites https to ssh and ssh-agent holds no identities. Machine
  quirk, not a repo problem — deliberately not committed as
  .cargo/config.toml. May or may not apply on the new machine.

- Ordnung fails its own required-dependencies: itertools missing from
  both crates, remeda and ts-pattern missing from site. Adding four
  currently-unused dependencies is a deliberate call, not yet made.

- website/.githooks is committed and executable but scripts/dev.sh
  never sets core.hooksPath, so a fresh clone of website runs no
  hooks. The local working copy has it set by hand. Two-line fix.
  This is the finding that validated the new git-hooks check.
